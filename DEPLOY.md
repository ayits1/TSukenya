# Деплой панелі «Цукерня»

Панель — один файл `app/index.html`, опублікований як Claude Artifact. Дані (товари, задачі, ідеї, витрати, налаштування) живуть **у базі артефакту**, а не у файлі й не в репозиторії. Звідси два правила:

- оновлення — це публікація нового `app/index.html` **у той самий артефакт** (за його посиланням): база лишається як є;
- новий артефакт стартує з порожньою базою, дані туди треба перенести (див. «Перенесення»).

## Середовища

| | Робоча панель | Тестова копія |
|---|---|---|
| Що це | артефакт, яким користується мережа | окремий приватний артефакт для перевірки нової версії |
| Де | посилання знає власник: у репозиторії його немає (таблицю «База товарів (з фільтрами)» веде інший Google-акаунт) | https://claude.ai/artifact/WbXmreEsZkRi9tu5uoA7ca |
| Маніфест можливостей | `deploy/capabilities.json` | `deploy/capabilities.staging.json` — без Google Sheets |
| Дані | живі | копія товарів; у `settings/main` поле `envLabel: "Тестова копія"` (видно в шапці) |
| Google-таблиця | підключена | **не підключати**: тестова копія не повинна чіпати робочу таблицю |

## Перед випуском

1. CI зелений: `npm run check` (те саме запускає GitHub Actions — `.github/workflows/checks.yml`).
   `tests/deploy.test.js` перевіряє правила артефакту: без `confirm()`/`alert()`/`prompt()` і `window.print()` (у рамці артефакту вони не працюють), без власних `<html>/<head>/<body>`, лише дозволені CDN, усі можливості й інструменти конекторів оголошені в маніфесті.
2. `APP_VERSION` в `app/index.html` і перший запис `CHANGELOG.md` збігаються (перевіряє тест).
3. PR злито в `main`, на коміті злиття — тег `vX.Y.Z`.
4. Тестова копія оновлена з того самого коміту й пройшла чек-лист «Після публікації».
5. Резервна копія робочих даних: у робочій панелі «План → Резервна копія → Зберегти копію». Файл JSON зберегти.

## Публікація

Публікує Claude з акаунта, якому належить робочий артефакт (або який має право його редагувати):

- `Artifact publish`: `file_path` = `app/index.html`, `url` = посилання на робочий артефакт;
- `capabilities` — вміст `deploy/capabilities.json`, лише якщо маніфест змінився з минулого випуску; інакше не передавати (збережеться чинний);
- відкриті вкладки отримають нову версію самі.

## Після публікації (5 хвилин)

- [ ] Внизу сторінки — нова версія.
- [ ] «Сьогодні» відкривається; кількість товарів і сума витрат — як до оновлення.
- [ ] У шапці «Таблиця · час» без помилки синхронізації.
- [ ] Змінити ціну одного товару — за кілька секунд вона в Google-таблиці; повернути назад.
- [ ] Видалити тестовий товар — натиснути «Скасувати» — товар на місці.
- [ ] «Цінники»: вибрати один товар — PDF зберігається.
- [ ] Claude: `ArtifactData list products` — кількість документів не змінилась.

## Відкат

Опублікувати попередню версію файлу в той самий артефакт:

```
git show v1.1.0:app/index.html > /tmp/index.html   # потім publish з url робочого артефакту
```

Дані не відкочуються — вони в базі; нові поля (`costAt`, `printedPrice`, `deletedProducts`, `sync/lock`, `targetMargin`) старі версії просто ігнорують.
**Не відкочуватися нижче 1.1.0, поки підключена таблиця:** версії до 1.1.0 очищують рядки з незнайомими ID і сприймають `confirm()`, що в артефакті не працює.

## Перенесення в новий артефакт

Коли старий артефакт недоступний для редагування (наприклад, опублікований з іншого акаунта):

1. У старій панелі: «Товари → Відключити» таблицю, потім зберегти резервну копію JSON.
2. Опублікувати новий артефакт із `deploy/capabilities.json`.
3. Надіслати JSON у чат Claude — він запише дані через `ArtifactData` з тими самими ID (товари, `deletedProducts`, задачі, ідеї, витрати, налаштування, крім `gsId`).
4. У новій панелі підключити ту саму таблицю: ID збігаються, синхронізація продовжиться.

Якщо копії JSON немає: підключити таблицю в новій панелі й натиснути «Забрати товари з цієї таблиці». Товари прийдуть із таблиці, а задачі, ідеї й витрати — ні.

**Ніколи не тримайте дві панелі підключеними до однієї таблиці.** З 1.2.0 панель сама зупиняє синхронізацію, якщо більшість ID у таблиці чужі («Цю таблицю веде інша панель»), і забирає таблицю лише після явного підтвердження.
