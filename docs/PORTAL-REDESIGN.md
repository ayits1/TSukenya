# Оновлення порталу · 30.09.2026

## Структура та оформлення

Портал для щоденної роботи власника торговельної мережі. Перший рівень навігації відділяє **Операційну роботу** від **Розвитку бізнесу**. Усередині першого простору — огляд, каталог, цінники, поточні задачі та витрати; у другому — огляд розвитку, ідеї й план реалізації. Прямі адреси розділів зберігаються в URL.

- Основа: `#F4F6F8`, папір `#FFFFFF`, текст `#172B3A`, підписи `#526575`, межі `#D7DFE6`, акцент `#205C91`.
- IBM Plex Sans — інтерфейс; Rubik за замовчуванням — друковані цінники. Табличні цифри у числових колонках.
- Етапи розвитку позначено звичайними номерами. Декоративні цукерки прибрано. Кольори стану мають текстові пояснення.
- Каталог на комп’ютері: назва та характеристики, закупівля, націнка, продаж, акція, редагування. На телефоні ці самі дані складаються у блок товару. 10/20/50 записів на сторінці.
- Розгорнуті панелі імпорту, Google-таблиці, масового оновлення й магазинів зберігають стан під час оновлення даних. Фільтри враховують інші вибрані умови; є фільтр акційних товарів.

Орієнтири, перевірені 30.09.2026: [Frontend Design від Anthropic](https://github.com/anthropics/skills/blob/main/skills/frontend-design/SKILL.md) та [Web Interface Guidelines від Vercel](https://github.com/vercel-labs/web-interface-guidelines/blob/main/command.md). Реалізація у чинному HTML/JS без зміни фреймворку.

## Конструктор та акції

1. Вибрати товари та копії.
2. Налаштувати макет: список елементів ліворуч, реальний товар у центрі, параметри вибраного елемента праворуч. Елементи макета доступні мишею та клавіатурою.
3. Перевірити всі аркуші А4, потім завантажити PDF або відкрити системний друк.

У кожного із 12 елементів окремі видимість, шрифт, фактичний розмір у pt, колір, насиченість і вирівнювання. Скидання стосується тільки вибраного елемента. Записи макета виконуються послідовно; показано збереження або помилку з можливістю повторення. Старі збережені розміри мігрують зі збереженням фізичного розміру друку (`styleVersion:2`).

`products.promotion` — ознака **Акція**. Вона доступна в каталозі та редакторі товару. На ціннику та у PDF з’являється жовта смуга «Акція», якщо увімкнено відповідний елемент. CSV експортує ознаку; CSV/XLSX імпорт розпізнає необов’язкову колонку «Акція» (Так/Ні). Якщо колонки немає, наявна ознака товару зберігається.

PDF малюється за розташуванням тексту, яке обчислив браузер для того самого HTML-макета: переноси, вирівнювання, розміри та шрифти відповідають перегляду. Він містить растрові аркуші 300 dpi; текст у PDF не є виділюваним. Перед виводом блокуються відсутні ціни, обрізаний текст і понад 1000 копій. Застарілі ціни вимагають підтвердження перевірки. На реальному принтері потрібно використовувати 100% без колонтитулів.

## Перевірка

`npm ci`, потім `npm test` та `npm run test:ui`. Для Linux потрібен Chromium Playwright (`npx playwright install chromium`) або `CHROME_PATH` до встановленого Chrome. На Mac використовується Chrome з `/Applications`. Потрібен Python 3 з scrypt. Тест браузера сам запускає сервер з окремою тимчасовою БД та видаляє її після завершення; до VPS він не звертається.

Перевірено створення товару, збереження акції після перезавантаження, незалежні параметри елементів, скидання одного елемента, міграцію розмірів, PDF, 22 копії на двох аркушах, виклик друку, блокування відсутньої ціни та переповнення, задачі обох просторів і перетворення ідеї на задачу. Розділи перевірено на 1440, 1024, 768, 390 та 320 px; окремо перевірено клавіатуру та темну тему. Контрольний PDF відкрито через Poppler і візуально оглянуто. Реальний принтер не підключено.

Google Sheets на VPS потребує окремого серверного доступу. Це оновлення не підключає автоматичну синхронізацію. Локальні резервні копії VPS не замінюють зовнішнього сховища.
