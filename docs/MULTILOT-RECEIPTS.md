# Кілька партій одного товару в надходженні (B11)

## Реалізовано

Одне надходження або документ початкових залишків може мати кілька рядків одного SKU з різними номерами партій або різними строками без явного номера. Ліміт — 200 рядків. Явний номер не довший за 80 символів; пробіли по краях вилучаються. Однаковий SKU + явний номер двічі в одній накладній відхиляється. Для двох партій з однаковим строком потрібно задати різні номери. Інші документи, крім повернення постачальнику, зберігають правило одного рядка на SKU.

Кожний рядок має незмінний `line_key` UUID. Збереження чернетки з цими ключами зберігає також первинний PK рядка; видаляються тільки вилучені рядки. Чужий ключ, повторений ключ та невалідний UUID відхиляються атомарно. Старий клієнт без ключа зберігає існуючий ключ/PK, якщо SKU у чернетці та запиті однозначний; для нових рядків ключ створює сервер. Ключ не змінює чинний механізм `idempotency_key` документа або контроль `revision`.

Надходження може розбити один рядок замовлення на кілька партій. `validate_reference_quantities` перевіряє суму всіх поточних рядків **на конкретний вихідний рядок** разом із попередніми проведеними поставками. Перевірка і проведення залишаються під `LedgerLock` в одній транзакції.

Повернення постачальнику вибирає конкретний рядок отриманої накладної через `reference_line`. Його ціна та ліміт кількості беруться з джерела. Партія/строк визначаються позитивним складським рухом цього рядка, а не першим рухом SKU. Одне повернення може включати різні отримані партії одного SKU, по одному рядку на кожний вихідний рядок. Якщо цієї фізичної партії вже недостатньо, операція відхиляється: інша партія не підставляється.

Борг і оплати залишаються на рівні однієї накладної `Voucher`. Додаткові витрати розподіляються по всіх її рядках пропорційно сумам: частки округляються вниз до копійки, залишок отримує найбільший рядок (при рівності — перший за PK). Сума складської вартості дорівнює повній сумі надходження. FEFO та чинне пропорційне списання вартості фізичної партії збережено; останнє списання забирає весь залишок копійок. Сторно зберігає зв’язок із рядком і лишається атомарним.

## Межа фізичної партії

Явний однаковий код SKU на одному складі у різних накладних **далі означає ту саму фізичну партію**; строки повинні збігатися. Запас і вартість об’єднуються, як і до B11. Походження повернення визначає договірну ціну та допустиму кількість, але складське списання використовує поточну вартість цієї спільної партії. Система не приписує її залишок одному надходженню після змішаних продажів. Для роздільного фізичного запасу потрібно ввести різні коди партій. Це збережена сумісність, а не новий облік FIFO за надходженням.

## API та інтерфейс

`POST /api/erp/vouchers`, `PUT /api/erp/vouchers/:id`:

```json
{
  "kind": "receipt",
  "reference": 12,
  "lines": [
    {"line_key": "6bc3b0ce-c3cd-4fe0-80c9-989d09703267", "reference_line": 31,
     "product": "sku", "quantity": "2.000", "price": "12.5000",
     "lot": "BATCH-A", "expiry": "2026-12-01"}
  ]
}
```

`line_key` і `reference_line` необов’язкові для старих клієнтів. Вихідний рядок має належати вибраному документу і SKU. Без явного `reference_line` сервер може підібрати його лише за однозначним SKU; якщо вихідна накладна має кілька партій цього SKU, потрібен конкретний рядок. `reference_line` без відповідного `reference` відхиляється.

Детальний DTO рядка додає `line_key`, `reference_line`; рух додає `line` (PK або `null`). Проведене надходження показує фактичний номер партії, включно з автоматичним `D...-L...`, і `origin_known`. Невстановлене історичне походження видно в деталях; неоднозначне повернення блокується. `remaining` та `remaining_amount` залишаються на рівні вихідного рядка. Грошові суми і кількості — decimal strings. Політика приховування собівартості для касира не змінена.

У формі можна повторно додати товар до надходження, зазначити різні партії та строки. Створення повернення переносить конкретні вихідні рядки, залишок, партію і строк; товар/партія/строк захищені від випадкової заміни. Заміна магазину або очищення пов’язаного документа очищає рядкові посилання. Дата/партія видимі в деталях документа. Перевірено клавіатуру і ширини 1440/390/320 px.

## Міграція

`0007_multilot_lines` залежить від `0006_legacy_create_receipt` (B06). Додає унікальний UUID до всіх існуючих `VoucherLine` без зміни PK або `reference_line`; `StockEntry.line` nullable/PROTECT. Пакетний backfill заповнює лише однозначний `voucher + product`. Витратні рухи виробничих компонентів та їх позитивне сторно залишаються `NULL`, навіть якщо компонент має SKU виходу. Сторно однозначного історичного рядка отримує той самий зв’язок. Неоднозначні записи не вгадуються. Міграція не змінює суми, кількості, ролі або проведення.
