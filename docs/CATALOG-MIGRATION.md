# Каталог на React · 01.10.2026

Каталог товарів інтегровано в чинний портал як React-модуль. URL `#operations/products` збережено. Django/PostgreSQL залишаються джерелом даних; складських або грошових проведень каталог не створює.

## Реалізовано

- Пошук за словами назви / штрихкоду та пагінація 10/20/50 на сервері.
- Залежні пошукові комбобокси: група → категорія → пакування; зміна батьківського фільтра скидає дочірні. Фільтри зберігаються при навігації між розділами.
- Компактна таблиця з цінами й акцією; на телефоні — картки без горизонтального виходу.
- Панель створення / редагування: назва, класифікація, пакування, одиниця, штрихкод, мінімальний залишок, закупівля, націнка, ручна ціна, акція та дата перевірки.
- Конфлікт версії: чужа зміна повертає HTTP 409, власний незбережений текст залишається в редакторі. Актуальний запис завантажується явною дією.
- Захист незбережених змін при закритті, переході між розділами та перезавантаженні. Видалення перевіряє версію та використання товару в обліку / рецептурі.
- Чинний імпорт CSV/XLSX, масове оновлення та цінники використовують ті самі документи. Масове оновлення «Показані за фільтром» враховує нові фільтри, а не лише поточну сторінку.

## Контракт та код

- `server/erp/catalog.py`: `/api/v1/session`, `/api/v1/catalog/products`, `/api/v1/catalog/products/{id}`.
- `contracts/catalog.openapi.json`: OpenAPI 3.1; `npm run generate:api` оновлює `frontend/src/shared/api/generated.ts`.
- `tools/api-contracts/`: генератор OpenAPI із сумісним TypeScript 5.9; frontend залишається на TypeScript 6.0. Peer-конфлікт не обходили `--force`.
- `frontend/src/features/catalog/`: мережевий адаптер, список, редактор, стилі, історії та синтетичні fixtures. TanStack Query керує серверним станом; React Aria — взаємодією.
- `frontend/src/catalog-entry.tsx`: монтування / демонтування модуля в чинній оболонці.
- `server/Dockerfile`: збирає Vite в окремому Node-етапі та копіює тільки готові assets у Python runtime.

Суми на новій API-межі — decimal strings; розрахунок продажної ціни виконується серверним Decimal з чинним округленням. Старі JSON-документи зберігають числові поля через явний адаптер сумісності. Редактор не змінює дату ціни при простому перейменуванні; зміна умов ціни або позначка «перевірено сьогодні» оновлює її.

Версія запису — HMAC від поточного вмісту документа та глобальних налаштувань ціни. Збереження й порівняння версії захищені тією самою транзакційною блокадою, що ERP та старий імпорт. Browser adapter передає `If-Match` для чинних товарів; старий API також відхиляє застарілий токен. Касир не отримує закупівлю й націнку та не може редагувати каталог.

## Пов'язані виправлення

Синхронізація з Google Sheets зупиняється до будь-яких записів, якщо зустрічає невідомий ID або не бачить раніше пов'язаного активного товару. Автоматичного очищення чужого рядка чи приховування за неповним аркушем більше немає. Сортування товарів обчислює індекс груп один раз на сортування.

Каталожну оцінку беззбитковості позначено як модель з рівними частками товарів; показано покриття даних. Фактичну структуру продажів та змінні витрати ця модель не замінює.

## Введення ціни гривнями та копійками

Ручна ціна продажу використовує спільний `MoneyField`: дві частини в одній рамці, «грн» і «коп.», один decimal-string для API. Кома/крапка переводить фокус до копійок; вставлення повної суми `21,99` або `21.99` у будь-яку частину розділяє її. Один введений знак у полі копійок означає одиниці копійок: `9` → `09`; при вставленні десяткової суми `21,9` означає `21.90`. Порожні копійки означають `00`; гривні обов'язкові. Значення не перераховується через JavaScript float. Перевірка форми відхиляє нечислові значення та понад дві цифри копійок; серверна валідація залишається чинною.

П'ять станів Storybook перевірено цільовими прогонами, включно з клавіатурою, вставленням, зовнішнім оновленням, валідацією та axe. Ізольований сценарій `QA_PRICE_ONLY=1` перевірив API-збереження/повторне відкриття `21.09` та вигляд 1440/390/320 px; знімки 1440/320 переглянуто. Збереження перевірялося у тимчасовій SQLite-базі; серверні обчислення й проведення не змінені, новий прогін PostgreSQL не виконувався. Компонент має власний scope фокусу, що працює і в портальному діалозі React Aria поза `.tk-root`.

## Календар перевірки ціни

React-редактор використовує спільний `DatePicker` на React Aria: локалізовані сегменти дати, календар з понеділка, кнопки «Сьогодні» та «Очистити дату». Календар доступний мишею й клавіатурою; Escape закриває його та повертає фокус кнопці. API отримує незмінений ISO date-only рядок, без перетворення через UTC. Сьогодні й верхня межа визначаються в Europe/Kyiv, майбутні дні недоступні. Явний вибір дати скидає прапорець priceReviewed, щоб він не замінив вибраний день сьогоднішнім. Зміна умов ціни надалі автоматично ставить сьогодні за чинним серверним правилом.

Перевірено типи, ESLint змінених компонентів, production build, шість станів Storybook із axe, вибір клавіатурою, Escape та повернення фокусу. `QA_DATE_ONLY=1` перевіряє календар у справжньому редакторі на тимчасовій SQLite: збереження минулого дня, повторне відкриття, очищення, київське сьогодні та межі 1440/390/320 px. Знімки 1440/320 переглянуто. Ізольований функціональний harness блокує зовнішній Google Fonts CDN та використовує системний fallback, щоб мережа шрифтів не затримувала запуск. Сценарій також включено до звичайного catalogue UI harness; повну регресію не запускали. Окремий скринридер і новий PostgreSQL-прогін не перевірялися; серверні обчислення та схема не змінені.

## Довідники товарів

Група, категорія, пакування, об’єм/вага та одиниця обліку використовують `/api/v1/catalog/references` і постійні документи `catalog_refs/`. GET об’єднує ці записи з сумісними історичними значеннями товарів; він не записує дані. `python manage.py seed_catalog_references` атомарно закріплює наявні значення без переписування товарів, повторний запуск створює 0 записів. POST створює запис незалежно від товару; однакові назви після нормалізації пробілів/регістру не дублюються. Категорії мають parentType, однакова назва дозволена у різних групах. Створення категорії закріплює також її групу, якщо та походила лише з історичного товару.

Редактор має комбобокси для пошуку й вибору та окреме «Додати» з полем нового запису, підтвердженням і скасуванням. Пошуковий текст не змінює дані товару; Enter у формі додавання створює довідник і не надсилає товар. Зміна групи очищує категорію іншої групи; категорія недоступна до вибору групи. Очищення знімає значення лише з товару, не видаляє запис довідника. Помилка зберігає набраний текст. Після додавання/скасування фокус повертається кнопці відкриття. При збою завантаження довідників можна повторити запит, збереження товару заблоковано.

Контракт товару поки передає канонічні текстові значення для сумісності зі старими модулями/імпортом. V1 перевіряє нові або змінені значення та зв’язок групи з категорією; незмінені історичні записи без групи можна редагувати. Старий імпорт продовжує працювати, його нові значення доступні в GET; команда seed може закріпити їх пізніше. API має ролі, CSRF, атомарність, спільний ledger_lock та аудит створення через POST. Окремі перейменування/видалення записів довідників ще не реалізовано.

Перевірено 12 серверних сценаріїв довідників та чинні 16 каталогу (PostgreSQL concurrency пропущено на SQLite), 3 API unit-сценарії, 6 історій редактора з axe, типи/lint/build. QA_REFERENCES_ONLY перевірив створення всіх п’яти видів, Enter/Escape, пошук без ручного запису, залежні категорії, збереження/повторне відкриття, збереження довідника після видалення товару та геометрію 1440/390/320 px; знімки 1440/320 переглянуто. Комбобокс має одну рамку фокусу і в портальному діалозі поза tk-root, кнопка списку має висоту 44 px. Повну регресію, новий PostgreSQL-прогін, скринридер і канонічні Linux PNG не запускали.

## Акційне ціноутворення

Звичайна сума залишається у чинних price/manualPrice або розраховується сервером із закупівлі/націнки. Nullable promotionPrice зберігається окремо. Під час promotion=true сервер застосовує її тільки коли 0 < promotionPrice < regularPrice; salePrice є діючою сумою. Вимкнення акції повертає regularPrice й залишає введену promotionPrice для наступного редагування. API передає гроші десятковими рядками; старий документний JSON має явний числовий адаптер.

Нові акції та зміни їх ціноутворення потребують окремої акційної суми. Старим товарам із самою позначкою не вигадується історична ціна: список/редактор показують пояснення, метадані можуть зберігатися без зміни цін через API. Увімкнення акції зі списку відкриває редактор; звичайна й акційна ціни редагуються окремими MoneyField. Чинна акція показує перекреслену звичайну суму; після зміни глобального округлення недійсна знижка не видається за діючу.

Каталог, студія й редактор продажу використовують однакову ефективну ціну. Касир бачить обидві публічні суми без закупівлі/націнки. Дата перевірки та версії змінюються разом з умовами акції. Імпорт/CSV/старий Google-sync розрізняють звичайну та акційну ціни; відсутні колонки не стирають дані. Спільна Google-таблиця перевірками не змінювалася; серверний Google-конектор не додано.

Цільові перевірки: 26 ізольованих серверних сценаріїв SQLite та ще 2 після уточнення адаптера; 2 API unit-тести каталогу; Storybook редактора/таблиці; QA_PRICE_ONLY — точне збереження 21.09 / 19.99, повторне відкриття, вимкнення/підготовка повторного ввімкнення, 1440/390/320 px. Обидва поля переглянуто на знімках. Старі 16 sync-сценаріїв і окремі сценарії legacy pricing/import пройшли. Постійна регресія — `npm run test:promotion:legacy`; її додано до явної повної перевірки. Повну регресію й PostgreSQL-конкурентність не повторювали: транзакційні межі не змінено.

## Гривні та копійки закупівлі · 01.10.2026

У ProductEditor закупівля використовує той самий MoneyField, що й звичайна/акційна ціна: дві частини в одному полі, перехід комою, вставка повної суми й точне decimal-string значення cost. Спільний контроль, API, розрахунок націнки та сервер не змінювалися.

Пройшли production build/типи, lint редактора, QA_PRICE_ONLY на ізольованій Django-базі: закупівля 6.07 зберігається й повторно відкривається як 6 грн / 07 коп., звичайна 21.09 та акційна 19.99 збережені, поля вміщаються на 1440/390/320 px. Жива перевірка підтвердила відновлення наявної суми, клавіатуру й компонування; чернетку відкинуто, товар до/після однаковий, catalogue mutation-запитів немає. Повна регресія не запускалась.
