## Подальша робота

1. Перед змінами прочитати `AGENTS.md`, обрати відповідну проєктну навичку та режим перевірки.
2. Отримувати актуальні refs через `git fetch origin`; нові робочі гілки створювати від актуального main з префіксом `codex/`.
3. Завантажувати робочу гілку через `git push -u origin <branch>`; у main зливати погоджені зміни. Зберігати commits/історію й виконувати потрібні CI gates.
4. Після публікації звірити SHA local/remote. Деплой VPS — окрема дозволена операція за [SERVER-DEPLOYMENT.md](SERVER-DEPLOYMENT.md).

Секрети `.private/`, `.env`, `.env.database`, live `storage/` та бази даних виключені з Git. Перед початковим push перевірено569blob локальної історії: пароль поточного власника й приватні ключі не виявлені; live DB/private paths не відстежуються. `data/` містить історичні стартові матеріали каталогу; це не експорт поточних проведень PostgreSQL. Synthetic Storybook/QA дані й PNG baselines зберігаються в Git.

Швидкі перевірки CI запускаються автоматично відповідно до workflow. Повний набір — лише явний `npm run test:full` або ручний workflow; це злиття не є запитом повної регресії.
