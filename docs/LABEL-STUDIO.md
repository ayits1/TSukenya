# Студія цінників на React · 01.10.2026

Маршрут `#operations/tags` використовує вибраний напрям «Студія шаблонів» у світлому оформленні «Робочий простір». Три етапи: **Макет → Товари → Перевірка**. Каталог і цінники тепер є робочими React-модулями; оболонка та торговельні екрани ще використовують `app/`.

## Робочий сценарій

- Макет: формати 58×40 / 75×50 / 100×70 мм; рамка; пошуковий комбобокс окремого товару з явним очищенням (серверні результати за назвою чи штрихкодом показуються без повторного фільтра в браузері); вибір поля на ціннику або у списку. На телефоні — вибір поля через Select.
- Кожне з 13 полів має видимість, шрифт, розмір у pt, колір, насиченість та вирівнювання. «Акція» показується тільки для акційного товару, якщо поле увімкнено. Дата цінника — дата підготовки друку; дата перевірки ціни залишається атрибутом товару.
- Назва мережі та список магазинів — реквізити макета, не нові ERP-магазини. Є готові оформлення (вибір не залишається в полі, тож той самий варіант можна застосувати повторно), скидання поля/макета та локальні undo/redo. Перетягування кольору — один крок undo. Зміна шрифту, кольору, насиченості чи вирівнювання зберігає лише цю властивість: незмінений розмір далі масштабується з форматом.
- Зміни є чернеткою до кнопки **«Зберегти макет»**. Редагує тільки власник; інші ролі можуть переглядати, обирати товари та друкувати. Перехід або перезавантаження попереджає про незбережені зміни. Конфлікт HTTP 409 залишає чернетку; завантаження актуального макета виконується явно. Якщо під час завантаження власник змінив макет, пізня відповідь не замінює ці правки й історію undo.
- Товари: пошук/залежні групи й категорії/акція, серверні сторінки по 20; кількість 1–500 на товар. Вибір зберігається між сторінками та переходами в межах відкритого порталу. Перезавантаження вкладки очищує локальний вибір.
- Переддрук: актуальні ціни із серверного Decimal, порядок група/категорія/назва; аркуші A4 з полями 8 мм. Для малого/середнього/великого формату місткість — 21/10/4 цінники. Екранний масштаб не потрапляє в друк.
- Відсутня ціна, прихована назва/ціна, обрізаний текст або понад 1000 копій блокують вихід. Застарілі ціни потребують підтвердження; нова перевірка скидає його. Перед PDF/CSV/системним друком серверний snapshot перевіряється повторно: якщо ціни або макет змінилися, потрібен новий перегляд.

## Межа даних та друк

`server/erp/labels.py`: GET/PATCH `/api/v1/labels/workspace`, POST `/api/v1/labels/prepare`. PATCH змінює тільки макет і його реквізити в `settings/main`, з HMAC-версією та чинною транзакційною блокадою ERP. Налаштування націнки/округлення/Google-доступу зберігаються. Старий шлях `/api/docs/settings/main` перевіряє ту саму версію в `If-Match` і після запису повертає нову `revision`; адаптер `server/runtime.js` бере її для наступного збереження, а запасний редактор `app/portal.js` зберігає від версії, яку показує, тож зміна макета з іншої сесії дає 409 замість тихого перезапису. Підготовка друку не створює складських або грошових проведень.

OpenAPI каталогу та цінників зберігається в `contracts/catalog.openapi.json`; типи генеруються командою `npm run generate:api`. API-сумам залишено decimal strings, перетворення на number виконується лише для форматування/візуалізації ціни. Власні розрахунки націнки React не виконує.

`frontend/src/features/labels/domain.ts` адаптує старі макети у `styleVersion:2` без повторного множення явних pt. Невідомі версії/властивості позначаються та блокують ненавмисне перезаписування. `Label.tsx` використовує той самий фізичний DOM для студії, аркушів і PDF; перевірка обрізання враховує переповнення й фізичні межі полів. Модуль `output.tsx` завантажується тільки при експорті: PDF A4, растровий 300 dpi; системний друк; CSV з BOM і роздільником `;`.

Vite `base: /frontend/` відповідає авторизованому маршруту статичних файлів Django, зокрема для лінивого PDF та preload CSS. Лабораторія Vite доступна під `/frontend/`; головна адреса dev-сервера перенаправляє на неї.

## Цільові перевірки

```sh
npm run check:frontend
npm run test --workspace frontend -- src/features/labels/api.test.ts src/features/labels/domain.test.ts
npm run test:components --workspace frontend -- src/features/labels/Studio.stories.tsx
PYTHON_BIN=.venv/bin/python npm run test:labels:ui
```

Браузерний сценарій використовує готову Vite-збірку та власну тимчасову Django-базу; робочий VPS і Google-таблиця не використовуються для мутацій. Серверні `tests.test_labels` включають версії, права/CSRF, обмеження та конкурентний запис; останній перевіряти на ізольованій PostgreSQL. Студію додано до явної `npm run test:full`; після звичайної правки повний набір не запускається.

Старий конструктор залишається fallback для середовищ без React-збірки. Старі його DOM-селектори вилучено з активних регресій: функціональна перевірка — `tests/labels-ui.cjs`, міграція макета — unit-тести. Google-серверний конектор, вільне перетягування полів та довільні нові розміри не додавалися. Фізичний принтер і скринридер потребують окремої перевірки.

## Перевірки початкового React-релізу

- Ізольована PostgreSQL: 19 сценаріїв каталогу/цінників, включно з конкурентним збереженням; доданий порядок груп/категорій окремо перевірено на SQLite.
- 9 unit-тестів адаптера/API; 8 сценаріїв студії Storybook пройшли сумарно основним і цільовим прогонами. Типи, lint і форматування frontend пройшли.
- Chrome з тимчасовою Django-базою: клавіатура, незалежне оформлення поля та reload, конфлікт 409 без втрати чернетки, 22 копії/2 аркуші A4, PDF, системний друк, зміна ціни після перегляду, відсутня/застаріла ціна, фізичне обрізання. PDF переглянуто через Poppler.
- Компонування студії перевірено на 1440/390/320 px; цільовий сценарій справжнього масштабу Chrome 200% пройшов. Знімки студії та PDF переглянуто вручну.
- Повна регресія `npm run test:full` у цьому релізі не запускалася; оновлені сценарії оболонки/каталогу синтаксично перевірені, окремо виконано потрібний сценарій масштабу. Нову студію у WebKit/Firefox та фізичний принтер цього разу не перевіряли.

## Звичайна та акційна ціни

Сервер постачає regularPrice, promotionPrice та діючу salePrice. Поле «Стара ціна» показує звичайну суму тільки за дійсної активної знижки й має власні шрифт/розмір/колір/вирівнювання/видимість. Перекреслення відтворюється в екрані, системному друці та растровому PDF. Старі макети версії 2 отримують увімкнене поле за замовчуванням без зміни інших стилів; без акції воно порожнє.

Позначка старого товару «Акція» сама по собі не доводить попередню суму. Якщо окремої акційної ціни немає або вона вже не нижча за звичайну, студія пояснює проблему та блокує вихід до виправлення товару/вимкнення акції. Довільну історичну ціну система не створює. «Стара» тут — поточна звичайна ціна товару, не журнал історії цін.

CSV містить звичайну, активну акційну та діючу ціни окремо; імпорт розрізняє ці колонки. Серверний snapshot охоплює обидві суми, тому зміна будь-якої потребує нового перегляду.

Перевірено цільово: 10 unit-тестів labels, Storybook PromotionPrices, ізольований Chrome-сценарій студії з обома сумами, блокуванням акції без суми, 22 копіями/двома A4, PDF та зміною акційної ціни після перегляду. PDF зі справжнім перекресленням переглянуто через Poppler. Фізичний принтер не перевірявся; повний набір і повтор PostgreSQL-конкурентності не запускали.

## Навігація вкладками · 01.10.2026

Вкладки «Макет», «Товари для друку» та «Перевірка перед друком» стоять на початку робочої області, одразу під заголовком сторінки. Повторний заголовок студії прибрано. Панель вкладок закріплена при прокручуванні; перемикання знизу довгої сторінки відкриває початок нового етапу. Чернетка, вибрані товари, копії та фільтри лишаються у спільному стані workspace. Клавіатурою працюють стандартні вкладки React Aria, активний етап і фокус видимі.

Цільова перевірка без PDF та повної регресії:

```sh
QA_NAV_ONLY=1 PYTHON_BIN=/path/to/python node tests/labels-ui.cjs
```

Пройшли production build/типи, lint зміненого React-компонента, ізольований браузерний сценарій: розташування, sticky, стрілки клавіатури, захист незбереженого макета, збереження чернетки/пошуку/копій, відсутність горизонтального виходу на 1440/390/320 px. Жива HTTPS-перевірка підтвердила компонування й стан без business mutation-запитів. Знімки комп’ютера й телефона переглянуто. Рендер цінника, фізичні розміри, сервер і PDF не змінено; їхній попередній результат перевірок збережено, повної регресії не запускали.


## Прогрес і скасування виводу · 03.10.2026

Студія показує кількість цінників і аркушів до запуску, а під час підготовки — перевірку актуальних цін, шрифти, захоплення макета і готові сторінки PDF. Кнопка «Скасувати підготовку» працює клавіатурою; після завершення фокус повертається на кнопку запуску. Якщо знімок цін змінився, фокус переходить до «Оновити перевірку».

Один AbortController передається повторному POST prepare (це читання знімка, не запис товару) й генератору. Скасування очікування шрифтів, canvas.toBlob, між сторінками та вихід із маршруту припиняють вивід без часткового файла. Чернетка макета, вибір, копії та чинний переддруковий перегляд залишаються. Пізня відповідь або callback не запускають завантаження й не змінюють новий маршрут. Підготовку системного друку теж можна скасувати; відкритий системний діалог закриває користувач. Print root прибирається через afterprint.

Рендер полів, raster 300 dpi, JPEG quality 0.92, A4/mm/pt та перевірки обрізання не змінені. Захоплення різних товарів поступається браузеру приблизно кожні 16 мс, між сторінками є окрема task boundary. Canvas скидається до 0×0 у finally, hidden React root видаляється. JPEG сторінки й фінальний PDF досі збираються в пам’яті.

Цільові докази:

- API: 3 unit-тести, включно зі скасуванням prepare та збереженим CSRF.
- 5 браузерних LabelOutput stories: очікування шрифтів для PDF/друку, encoder, міжсторінкове скасування/перед download, повтор/cleanup, максимальний пакет і захоплення 1000 різних товарів. Захоплення скасовується після першої реально завершеної порції.
- Окрема Studio story на 320 px: прогрес 1/2, Enter, повернення фокусу та повтор; це синтетичний UI-сценарій, не генерація файла.
- `tests/labels-output-ui.cjs`: справжній Studio та Django з тимчасовою SQLite, керовані запізнілі prepare/toBlob, 1440/390/320, реальні 200%, вихід із маршруту, збереження 22 копій/двох аркушів, зміна ціни після перегляду, скасування підготовки друку/повтор/afterprint і CSV-фокус. Runtime errors відсутні.
- PDF після повтору: 667 919 байтів, 2 A4; обидва embedded JPEG мають 2480×3508 px. Browser pixel-порівняння першого цінника на обох сторінках — 0 відмінних каналів, видимі назва/ціна/одиниця. Poppler підтвердив геометрію; обидві сторінки PNG переглянуті. Якщо Poppler відсутній, helper явно записує пропуск PNG-перегляду; перевірки вбудованих JPEG/MediaBox лишаються обов’язковими.
- Синтетичні 1000 копій найбільшого формату: 250 A4, 300 dpi, 49 916 285 байтів і 10 413 мс у Chrome/macOS. Це конкретний макет/комп’ютер, не прогноз для всіх пристроїв. Оцінка алокацій canvas ≈34.8 МБ, JPEG ≈49.9 МБ, фінальний Blob ≈49.9 МБ; native peak memory не виміряний. Межа 1000 загалом/500 на товар збережена.

## Порційна пам’ять й аркуші · 04.10.2026

Переддруковий перегляд показує обраний аркуш; комбобокс з пошуком номера та «Попередній/Наступний аркуш» дозволяють переглянути будь-який із них. Всі копії залишаються для PDF/actual print. Обрізання перевіряється для всіх SKU порціями поза екранним zoom, включно з непереглянутими аркушами; помилка шрифтів має повтор. PDF тримає DOM одного A4, LRU32 макетів і JPEG Blob parts без повного набору ArrayBuffer copies.

RSS proxy виміряний до/після на синтетичних 1000 різних SKU; один запуск не доводить native memory upper bound чи телефонну capacity. Скасування/повтор і expiry URL перевірені. Інтерактивний перегляд теж обмежений одним A4; browser print формує повний DOM тільки на час друку. Числа, метод, неперевірені межі, фізичний PDF/keyboard320 докази — [LABEL-MEMORY.md](LABEL-MEMORY.md).
