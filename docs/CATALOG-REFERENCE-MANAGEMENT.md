# Керування довідниками каталогу · B30

У каталозі кнопка **Довідники** відкриває React-редактор груп, категорій, пакувань, об’єму / ваги й одиниць обліку. Перегляд доступний авторизованим ролям; зміни — чинним `EDIT_ROLES` (`owner`, `manager`, `warehouse`). Сервер повторно перевіряє роль і активність користувача після отримання облікового блокування, також для повторного підтвердження.

## Дії та межі

- **Перейменувати**: стабільний ID зберігається; поточні товари отримують новий підпис. Зміна групи також оновлює прив’язку її активних та архівованих категорій.
- **Об’єднати**: потрібен явно вибраний активний цільовий запис. Категорії об’єднуються лише всередині однієї групи. При об’єднанні груп однойменні активні категорії переходять до категорії вибраної цільової групи; решта категорій зберігає ID й отримує новий `parentId`. Перелік злиттів видно до підтвердження.
- **Архівувати**: старі значення й версії товарів не переписуються. Запис вилучається з нового вибору; його попередні назви та значення зі старих товарів не відновлюють активний запис. Це стосується й типової одиниці `шт`.
- **Відновити**: ID зберігається. Активний запис із тотожною назвою чи alias у тій самій групі блокує відновлення без запису або аудиту. Редактор пояснює, що треба відкрити наявний активний запис або спочатку звільнити його назву.
- Використані одиниці обліку захищає B03: рецептури, облікові рядки й складські партії блокують їх перейменування або об’єднання. Перевірка виконується після нормалізації alias, тому старий текст не обходить захист.
- Історичні `VoucherLine.name/unit`, замовлення, партії й облікові рухи залишають свої дані. Приховані поточні товари враховуються в preview. Невідомий ID не означає архівування; незмінений коректний ID зберігається при редагуванні метаданих.

## Перевірений вплив і повтори

1. `GET /api/v1/catalog/references/manage` повертає стани й версії всіх записів.
2. `POST /api/v1/catalog/references/preview` перевіряє `{sourceId, revision, operation, value? / targetId?}` і повертає read-only вплив: кількість використань, товарів і записів для зміни, приклади, злиття категорій, блокування та підписаний `snapshot`.
3. `POST /api/v1/catalog/references/commit` додає `snapshot` і `idempotencyKey` UUID. У транзакції під спільним `ledger_lock` сервер повторно обчислює вплив, змінює довідники й поточні товари та пише один `catalog_reference_changed` з безпечними `before` / `after` довідників. Помилка відкочує всі записи й аудит.

Зміна версії або впливу повертає 409. UI зберігає введену назву, скидає старий preview й потребує нового перегляду перед підтвердженням. Зміна форми чи запізніла відповідь також не залишає старий preview доступним для запису. Після втрати відповіді кнопка повторює точний початковий запит із тим самим UUID; сервер повертає початковий результат навіть після наступних редагувань. Інший запит із використаним ключем отримує `idempotency_conflict` без нового запису або аудиту.

`Product.referenceIds` — read-only карта сервера. `ProductCreate` / `ProductPatch` не приймають її; runtime decoder перевіряє дозволені ключі й формат ID. `ReferenceData.archivedItems` забезпечує читабельний підпис **Архівований** та явне пояснення у старому редакторі. Наявний товар може зберегти незмінене архівоване значення; новий товар потребує активної одиниці. Ціновий preview B28 не створює й не переприв’язує довідники.
