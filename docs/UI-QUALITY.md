# Перевірка верстки

Повторні дефекти контролів виникли через незалежні стилі в робочому застосунку й новому прототипі. Виправлення робочого select не потрапило до прототипу. Перевірка загального переповнення сторінки цього не виявила.

## Правила реалізації

- Для кожного типу контролу використовувати один компонент або спільний CSS-клас. Варіанти оформлення змінюють палітру, а не геометрію стрілки чи внутрішні відступи. Під час перенесення погодженого прототипу в застосунок перенести і компонент, і його перевірки.
- Зберігати нативний `select`, доступну назву, клавіатуру та видимий фокус. Для декоративної стрілки резервувати місце праворуч; стрілка не перехоплює натискання. У режимі високої контрастності повертати нативний індикатор.
- У звичайному рядку вирівнювати висоти полів; компактна панель має окремий спільний розмір. Довгі назви не повинні перекривати стрілку. Для сенсорного екрана забезпечувати ціль щонайменше 44 × 44 px.
- Не замінювати візуальний контроль перевіркою `scrollWidth`. Вона виявляє тільки загальне переповнення, а не криву іконку, обрізаний текст, зміщений заголовок чи неправильний фокус.

## Перед завершенням зміни інтерфейсу

1. Перевірити змінені компоненти за обох системних тем на широкому й вузькому екранах (портал має один світлий вигляд), з короткими та довгими значеннями. Переглянути отримані скриншоти.
2. Пройти основну дію клавіатурою. Перевірити збереження фокусу після перемальовування.
3. Перевірити геометрію індикаторів і текстового поля, розміри іконок, вирівнювання висот, переноси панелей та сенсорні цілі.
4. Для таблиць і закріплених заголовків перевірити прокручування та межі їхнього контейнера. Для діалогів — фокус, довгі поля й вузький екран.
5. Для виправленого повторного дефекту додати перевірку, що відтворює саме дефект. У звіті назвати перевірені браузери та відрізняти прототип від розгорнутого застосунку.

## Автоматичні перевірки

Єдиний світлий напрям, перший етап: `npm run test:workspace:ui`. Відкриває локальний `design/workspace.html`, без сервера CRM та мережевих запитів. Перевіряє пошук, фільтри, порожній результат, створення й редагування демонстраційного товару, довгі назви з HTML-символами, великі суми, геометрію контролів, підписи кнопок, колір основної дії та повернення фокусу після закриття редактора. Ширини 1440/1024/768/390/320 px; світлий вигляд при обох системних темах; окремо сенсорні цілі та високий контраст. Спільні контролі визначені в `app/ui.css`.

Робочий портал: `npm run test:layout:ui` — індикатори select у каталозі, редакторі товару й CRM, а також прокручування заголовків категорій. Тест запускає окремий локальний сервер із тимчасовою базою.

Новий прототип: `node tests/design-controls.cjs /absolute/path/to/rendered-preview.html`. Спочатку створити самостійну сторінку перегляду штатним `visualize/scripts/render.py`. Тест перевіряє обидва варіанти оформлення, світлу й темну теми, ширини 1024/736/390/320 px, відступ і центрування стрілок, місце для короткого тексту, висоти контролів, перехід клавішею Tab, фокус після зміни значення, сенсорні цілі й режим високої контрастності. Використовує Chromium із Playwright у headless-режимі, без channel/executablePath. Обмеження автоматизації системного select фіксувати як неперевірене; не обходити їх запуском видимого системного Chrome.

Ці перевірки не є повним аудитом доступності або гарантією однакового відображення в Safari та Firefox. Після вибору дизайну його перенесення в застосунок потребує окремої перевірки реальних екранів і даних.

## Робочий реліз · 01.10.2026

- `npm test`: сценарії синхронізації після винесення коду до `app/portal.js`.
- `npm run test:ui`: каталог, акція, 12 інспекторів, збереження/скидання, старі фізичні розміри, блокування друку без ціни чи з обрізанням, PDF, 22 копії на двох аркушах, задачі й ідеї; п’ять ширин.
- `npm run test:crm:ui`: надходження, продаж, повернення, собівартість, залишки, гроші, борги та зарплата «ставка + % виторгу магазину»; вісім екранів і редактор продажу на п’яти ширинах.
- `npm run test:layout:ui`: селекти, прокручування категорій, світлий вигляд за обох системних тем, мобільний вибір елемента й навігація, запізніла відповідь CRM після переходу. Chrome також перевіряє сенсорні висоти 44 px, високий контраст і справжній масштаб браузера 200%: тимчасовий профіль, вікно 1440 px, `innerWidth=720`, `devicePixelRatio=2`. Це не CSS `zoom`.
- `QA_BROWSER=webkit npm run test:layout:ui`: ті самі перевірки компонування й переходів у WebKit; без Chrome-специфічного профілю масштабу.
- Візуально переглянуто каталог на телефоні, редактор товару, конструктор на широкому та вузькому екранах, звіти, команда й контрольний PDF через Poppler. PDF має A4; фізичні формати цінників збережені, збільшення перегляду на екрані не застосовується до друку.

Перевірка реального VPS — вхід, хеші файлів, усі 16 маршрутів і мобільні контролі. Запити на зміну облікових документів у цій перевірці блокуються. Візуальна перевірка виявила гонку: стара відповідь торговельного простору могла перезаписати наступний розділ помилкою прав. Виправлено перевіркою покоління запиту; регресія навмисно затримує відповідь на 250 ms.

Перевірено Chrome та WebKit Playwright на macOS. Це не повний аудит доступності, не перевірка Firefox/системного Safari й не випробування фізичного принтера. Знімки тестів поки є матеріалом ручного огляду; автоматичне порівняння з затвердженим користувачем еталоном ще не налаштовано.

## Комбобокс товару · 01.10.2026

Поле «Товар для перегляду» тепер редагований комбобокс (`app/combobox.js`, спільні стилі `app/ui.css`). Клік відкриває список; введення звужує його за словами назви без урахування регістру. Стрілки переміщують активний варіант, Enter обирає; Escape, Tab і вихід з поля зберігають раніше вибраний товар. Невідомий текст не створює товар і не змінює макет. Підказки обмежено першими 60 результатами; для інших товарів потрібно уточнити назву.

Підпис поля, ролі combobox/listbox/option, aria-expanded, aria-controls і aria-activedescendant; DOM-фокус залишається в полі. Список розташовується зверху або знизу за доступним місцем. Назви потрапляють у DOM через textContent. Введення/вибір змінює тільки товар перегляду, без запису в каталог.

Регресії: відкриття списку кліком, пошук українських назв і кількох слів, вибір мишею/Enter, стрілки, скасування, порожній результат, повернення фокусу та відповідність товару в макеті. Окремо Chrome/WebKit на 1440/768/390/320 px, геометрія стрілки й межі списку, сенсорна висота, масштаб 200%. Скриншоти відкритого списку на 1440 і 390 px переглянуто; сценарії друку й PDF залишаються справними.

Орієнтир взаємодії: [WAI-ARIA Combobox Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/). Це перевірка DOM/клавіатури в браузері, а не окремий аудит зі скринридером.

## Робоча React-студія · 01.10.2026

Студія використовує спільні React Aria ComboBox/Select у Storybook та в порталі. Одна рамка фокусу належить групі комбобокса: вкладені input/button не отримують додаткового outline від старої оболонки. Регресія `tests/labels-ui.cjs` перевіряє відсутність внутрішньої рамки й видиму зовнішню після вибору клавіатурою. Це доповнює перевірку положення індикатора, а не замінює її.

Огляд поточної студії: Chrome, 1440/390/320 px, індивідуальний макет, інспектор/мобільний вибір поля, переддрукові аркуші й PDF. Справжній масштаб 200% перевірено цільовим сценарієм компонування. Фізичні межі кожного поля перевіряються перед виходом; екранне збільшення не змінює mm/pt. Перелік сценаріїв і неперевірені межі — [LABEL-STUDIO.md](LABEL-STUDIO.md).

## Бюджет витрат · 01.10.2026

Виправлено стискання назв статей полем ui-input із width:100% у flex-рядку. Рядок бюджету тепер має окремі колонки для назви, суми/валюти та видалення. Container query переходить до назви над сумою, коли сама колонка бюджету вужча за 420 px; це працює також у двох колонках на проміжній ширині екрана. Додавання статті використовує сітку; поле суми й кнопки мають ціль не менше 44 px. Чинне автозбереження та фінансові розрахунки не змінювалися.

Цільова регресія: `PYTHON_BIN=/path/to/python node tests/expenses-ui.cjs`. Вона запускає тільки локальний сервер із тимчасовою базою: «Оренда» не переноситься по літерах, довгі назви не перекривають суму, обидві системні теми, 1440/1024/768/390/320 px, геометрія й автозбереження 12345.67 із повторним відкриттям. Пройшла в Chrome; знімки 1440/390 px переглянуто. Повної регресії не запускали, WebKit окремо для цієї зміни не перевірявся.


## Прогрес PDF · 03.10.2026

Новий статус і cancel використовують чинні Button/CSS-токени. Status стоїть поза aria-busy action region; перевірка знімка/модуля має невизначений progress, етапи capture/pages — completed/total. Підготовка блокує зміну параметрів; скасування повертає фокус до джерела, конфлікт — до повторної перевірки. Storybook покриває 320 px / Enter / повтор; справжній Studio — 1440/390/320 і actual 200%, ціль ≥44 px, межі viewport. Докази фізичного PDF/cleanup і невиконані ручні перевірки — [LABEL-STUDIO.md](LABEL-STUDIO.md).

Для великих пакетів інтерактивна студія монтує один A4. Пошуковий комбобокс номера та кнопки аркушів використовують спільні React Aria/CSS; Enter і повернення фокусу після переходу перевірені на native320 та Storybook320. Валідація всіх SKU порційна й не залежить від видимого аркуша. PDF/копії/фізичні розміри збережені. Докладні memory proxy та PDF/pixel/cleanup докази — [LABEL-MEMORY.md](LABEL-MEMORY.md).
