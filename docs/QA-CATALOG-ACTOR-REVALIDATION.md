# Каталог: актуальні права після очікування ledger lock

Дата: 2026-10-04. Вихідний код: `9c04dad2b48ac59b1b544ec44e4857e273147de6`.
Перевірки виконано на локальній ізольованій PostgreSQL 18, базі
`test_tsukenya_catalog_security`; Django 5.2.17, psycopg 3.3.6.

## Відтворення до виправлення

Тест отримує кешований `User` із `Profile`, утримує `LedgerLock` іншою
транзакцією й перевіряє через `pg_stat_activity`, що запит справді чекає
PostgreSQL lock. Потім змінює роль, активність або магазин і відпускає lock.

На незміненому вихідному коді чотири цільові тести дали 14 очікуваних FAIL:

- Відкликана роль: імпорт, переоцінка, створення/зміна/видалення товару,
  створення довідника, макет цінника, створення/архівування акції прийнято
  з відповідями 200/201.
- Деактивація під час очікування не зупинила імпорт.
- Обмеження власника магазином не зупинило точний повтор створення акції
  або її архівування.
- Точний повтор імпорту/переоцінки повернув квитанцію після відкликання ролі.

Локальний журнал: `/tmp/tsukenya-catalog-security-before-lock-proof.log`.

## Виправлення й докази

`catalog_access.revalidate_actor` перечитує активність користувача та його
профіль після ledger lock, перед будь-яким записом або поверненням квитанції.
Зберігаються чинні правила спільного каталогу: власник з магазином може
змінювати ціни/макет, менеджер/склад — дозволені товари/довідники/імпорт.
Акціями мережі надалі керує лише власник без обмеження магазину.

Сім нових PostgreSQL тестів PASS: дев'ять варіантів запису з відкликаною
роллю, деактивація, точні повтори та очікування перед ними, чинний магазин,
відсутність записів/аудиту при відмові, збережений доступ допустимих ролей.
Кожен конкурентний сценарій перевіряє фактичне очікування lock.

Вісім наявних цільових сценаріїв PASS: квитанції імпорту/переоцінки після
зміни каталогу, змінений запит або інший автор з тим самим ключем, сумісність
власника з магазином для цін/макета/бюджету, ревізія макета, повтор і
архівування акції. Разом перевірено 15 різних тестів; повний набір не запускався.

Журнали: `/tmp/tsukenya-catalog-security-after.log`,
`/tmp/tsukenya-catalog-security-lock-proof.log`.

Для повтору нового захисту задайте змінні ізольованої PostgreSQL бази й виконайте:

```sh
python manage.py test tests.test_catalog_actor_revalidation --noinput
```

На SQLite ці тести явно пропускаються: вона не доводить PostgreSQL row locking.
