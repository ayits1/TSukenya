## Межа й actual consumer

- `NativeCategoryPersistence` + P0 codec `native-category-v1`: versioned same-tab/same-session storage. Явні `name:string` (до8000 raw символів) та `active:boolean`; raw whitespace/порожнє ім’я не нормалізуються. Save-validator окремий; DOM maxlength160 і чинні серверні правила незмінні. Baseline містить лише UUID/name/active/revision/semantic_key; aliases, facts, permissions, credentials, csrf та full caches не записуються.
- Durable перші method/path/UUID/body/revision **до fetch**. CREATE unknown/reload/пізніший4xx — exact typebutton або creator-bound identity. Новіші invalid поля не змінюють firstbody. UPDATE unknown — current GET/explicit comparison/Apply, окремий Save; blind PUT replay немає.
- CREATE ACK/identity підтверджують ID та frozen projection, **не поточну ревізію**. Identity підтвердження записується до будь-якого незалежного current GET. Current503/role/malformed/reload не повертають форму до нового CREATE. Current-read після ACK — обов’язковий barrier перед cleanup; newer raw збережено. Explicit Apply приймає перевірену поточну ревізію й очищає старий intent; Save окремий.
- UUID, semantic_key, aliases та історія не входять у writable merge. Name/active лишаються незалежними shared conflict fields. Tombstone не створюється заново; legacy_unknown не є доказом відсутності UUID. Існуючі creator receipt/normalized fingerprint/locks і правила past budget/store/aliases не змінювались; нових моделей/міграцій немає.
- Fresh session + `GET budget-categories/recovery-context?id=` у реальному READ ONLY RR перед приватним DOM; strict context actor/role/store binding. Category — чинний shared ресурс: owner/manager/accountant read, owner edit включно scoped owner. `canEdit=false` не означає видалення дозволеної чернетки. Permissions не відновлюються зі storage; actual Save проходить fresh P0 і server authorization.
- Current/identity та after-ACK current проходять P0 verifyRead; header/body/footer приховано, public access retry GET-only і Cancel доступні. Resource403 стирає лише denied record; role/store/session changes та401 — session-bound записи.503/protocol не стирають дозволені дані. Cold Restore явний; authorize → async renderer з abort/route/generation fences; nested controller.check під час Restore немає. Warm verify повертає ту саму форму; dismiss recovery не знищує restored editor. Close залишає локальну чернетку до explicit Discard/confirmed cleanup.
- Перший **live** CREATE400 звільняє intent лише при key/resource-bound `write_rejected` після rollback save_category. Wrapper не охоплює Conflict/authorization або помилку відповіді після commit. Після unknown/reload будь-який пізніший400 не відпускає first intent. Proof не є глобальним «UUID не існує».
- Actual monthly category host/onSaved лишається сумісним: Apply не змінює plan draft, Save оновлює readonly choices без стирання виторгу. Cold Restore з огляду монтує незалежний category dialog; він не створює та не відновлює місячний план.
