# Перевірка прав задач і приватності налаштувань

## Межа та ізоляція

Сценарій `tests/task-scope-ui.cjs` запускає власний Django на локальному порту 18217 і тимчасовій SQLite. Успадковані параметри PostgreSQL вилучаються; зайнятий порт зупиняє сценарій до створення fixtures. Користувачі та документи синтетичні. База й процес прибираються після завершення. VPS і Google-таблиця не використовуються.

```sh
PYTHON_BIN=/tmp/tsukenya-crm-venv/bin/python node tests/task-scope-ui.cjs
```

Для повтору лише змінених перевірок навігації: `QA_NAV_ONLY=1`; для окремих ролей: `QA_ROLE=manager,cashier`. `QA_CONTROLS_ROLES=cashier` перевіряє навігацію вибраних ролей і новий сценарій керування лише касира.

## Правила, які перевіряються

| Роль | Задачі магазину | Мережева задача | Системне нагадування | Розвиток |
| --- | --- | --- | --- | --- |
| Власник | Перегляд, статус, видалення ручної задачі | Редагування | Статус; без видалення | Повний доступ; legacy задачі без scope збережено |
| Менеджер магазину A | Редагування A; B не повертається | Лише перегляд | Статус у A; без видалення | Навігація прихована; прямий URL показує пояснення |
| Касир магазину A | Лише перегляд A; B не повертається | Лише перегляд | Лише перегляд | Навігація прихована; прямий URL показує пояснення |

В інтерфейсі використовуються серверні `item.permissions`, передані адаптером `snapshot.permissions()`. Клієнт не зберігає їх у `Document.data`. Менеджер створює operations задачу без ручного store; сервер присвоює його магазин. Зміна статусу нагадування не змінює `_alertKey`, `_alertActive`, дату, магазин або інші системні реквізити.

## Серверні результати

- 8 цільових сценаріїв `tests.test_task_scope` для scope, відомих ID, ролей, мережевих задач, auto metadata та підміни permissions — PASS.
- Чинний `AdditionalAccountingTests.test_alerts_are_deduplicated_and_resolve` — PASS.
- 2 додаткові сценарії settings DTO та серверної ціни касира — PASS. Owner отримує повні settings/project; non-owner — публічні реквізити цінника, додаткові pricing defaults лише manager/warehouse/accountant. Інтеграції, бюджет і невідомі ключі приховано. GET не записує дані; nested DTO незалежний від source; revision макета та `canEdit=false` збережені.

Повну регресію не запускали. SQLite тут перевіряє права та DTO; облікові проведення й конкурентність не змінено.

```sh

```

Раніше успішні owner та manager controls перевірки використано повторно: їхній код після успіху не змінювався.
