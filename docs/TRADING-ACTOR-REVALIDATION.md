# Поточні права після очікування облікової блокади

04.10.2026, вихідний main `8664a7650db546f0c92e0ba116d2700943e68873`.

## Виявлена прогалина

Middleware завантажує користувача та profile до початку торговельної
операції. Під час очікування LedgerLock активність, роль або магазин можуть
змінитися. Попередні save/post/reverse, касові зміни й деякі довідники та
налаштування використовували цей закешований об'єкт. Ізольоване відтворення
відключеного cached actor дало дев'ять відсутніх очікуваних відмов, включно
з повтором створення й поверненням уже проведеного документа.

## Виправлення

`services.current_actor` після ledger lock перечитує активний User із
наявним Profile одним запитом. До permission/scope або retry ACK перевірки
отримують поточну роль і магазин. Початковий principal також отримує свіжий
profile: HTTP-код може серіалізувати результат тим самим об'єктом, тому
дозволений продаж після переходу owner→cashier не повертає cost/value.
Відсутній profile дає бізнес-помилку, а не внутрішній AttributeError.

Охоплені операції:

- створення/редагування/проведення/скасування документа та exact retry;
- видалення чернетки; відкриття/закриття касової зміни;
- торговельні довідники й асортимент складу;
- статті та місячні бюджети;
- legacy рецептура, зміна закритого періоду;
- користувачі/ролі, режим ПРРО та ліміт знижки.

Зміна користувача/ролі через штатний API тепер бере той самий ledger lock.
ПРРО-налаштування та їх аудит атомарні; попередній ліміт знижки для аудиту
читається під lock. Правила доступу, магазини, суми, склад і payroll формули
не розширені. Міграції не потрібні. B04 та каталог уже мали свою повторну
перевірку; новий пакет не замінює їхні захисти чи import job contract.
