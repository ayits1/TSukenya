# Пам’ять PDF і порційний перегляд · B32 · 04.10.2026

## Що обмежено в коді

- PDF рендерить DOM тільки для поточного фізичного A4: не більше 21/10/4 цінників для s/m/l. Захоплені макети зберігаються в LRU максимум на 32 SKU; копії використовують чинний макет без повторного захоплення, доки він є в кеші.
- Один canvas A4 2480×3508 px, 300 dpi; це близько 34.8 MB RGBA, а не загальна пам’ять браузера. JPEG quality 0.92, фізичні mm/pt, рамка, акційна позначка/стара ціна та перевірка обрізання збережені.
- `RasterPdf` послідовно додає незмінні JPEG Blob parts. Немає масиву всіх JPEG ArrayBuffer і перетворення кожної сторінки через `arrayBuffer()`. Повний фінальний файл однаково потребує backing storage браузера; це не обіцянка constant-memory streaming на диск.
- Скасування очищає writer parts, hidden React root і canvas. Частковий PDF не завантажується. Завантажений Blob URL живе до 60 секунд, як раніше: повторні завантаження до цієї межі можуть утримувати попередні файли. Після межі URL звільняється; RSS може залишатися в кешах/алокаторі браузера.
- Інтерактивний переддруковий перегляд показує **один обраний аркуш**. Номер можна знайти в комбобоксі або перейти кнопками. Усі копії залишаються у snapshot й actual print/PDF.
- Перевірка обрізання автоматично охоплює **всі унікальні SKU**, незалежно від переглянутого аркуша: окремий hidden host обробляє по одному A4 без екранного zoom. Вивід дозволяється тільки після повної перевірки поточного snapshot. Помилка завантаження шрифтів має повтор; зміна snapshot/вихід скасовує стару перевірку й прибирає host.
- Browser print монтує повний фізичний print DOM тільки під час підготовки/системного друку й очищає його через afterprint. Це окрема, наразі не порційна пам’ять самого print pipeline.

Межі 1000 цінників загалом і 500 копій на товар збережені. Немає мовчазного обрізання списку, зменшення dpi або фізичного масштабу.

## Вимірювання на цьому комп’ютері

Окремий Chrome 154.0.8037.93/macOS, Vite laboratory, синтетичні 1000 **різних** товарів, l/250 A4, частина з акцією, unit кг/per100. Послідовність: один прогрів → повний експорт → скасування на сторінці 2 → повторний експорт → 61 секунда для expiry URL → GC для окремої heap-метрики. Захоплення фізичного принтера/телефона відсутнє.

Метод native proxy: кожні 100 ms `ps` знімає **суму RSS KiB окремого Chrome process tree**. Shared pages можуть враховуватися кілька разів; це не PSS, physical footprint, peak усієї системи або оцінка RAM телефона. Одна пара запусків не встановлює верхню межу native пам’яті. Примусовий GC і `Runtime.getHeapUsage` після операцій — окрема метрика, яка не включає всю графіку/Blob storage.

| Метрика | До | Після порційного PDF |
| --- | ---: | ---: |
| DOM цінників export host, формат l | 1000 | 4 |
| Перший експорт, ms | 6412 | 6383 |
| Перший Chrome RSS proxy peak, MiB | 1374.4 | 1354.8 |
| Перший RSS приріст від прогріву, MiB | 292.5 | 243.2 |
| Скасування на другій сторінці, ms | 1533 | 61 |
| Повторний експорт, ms | 6726 | 6313 |
| Повторний RSS proxy peak, MiB | 1395.1 | 1424.1 |
| Повторний приріст від поточного baseline, MiB | 164.6 | 139.3 |
| PDF bytes, 250 A4 | 66 804 594 | 66 804 757 |
| RSS proxy після URL expiry, MiB | 782.7 | 770.7 |
| Активні URL після expiry | 0 | 0 |

Перший приріст менший приблизно на 49.4 MiB; абсолютний пік повтору більший на 29 MiB. **Загального зменшення native peak ці два запуски не доводять.** Підтверджений результат — обмежений DOM/кеш/відсутність JPEG ArrayBuffer copies, швидше скасування цього пакета і звільнення URL. Різниця 163 bytes великих JPEG-пакетів не означає зміни dpi/геометрії: позиція DOM-захоплення й дробові координати можуть змінювати JPEG bytes. Фізичний PDF окремо перевірений нижче.

## Цільові докази

- Два pure `rasterPdf` тести: Blob JPEG без ArrayBuffer capture, binary-safe xref offsets, A4 595.28×841.89 pt, 2480×3508 JPEG; неповний/скасований writer не видає partial PDF.
- LabelOutput stories: fonts abort/retry, між сторінками й перед download, promotional/per100 packet із максимум чотирма hidden label DOM і забороною JPEG `arrayBuffer()`.
- ReviewPages story: 1000 SKU/250 аркушів, пошук 250 клавіатурою, повернення назад/фокус, 320px/44px. Обрізаний SKU на **останньому невидимому аркуші** входить у результат повної перевірки ще до навігації; hidden host очищений.
- Зібрана справжня Studio з приватним Django/SQLite: native320 keyboard page navigation зберігає всі 22 копії; після PDF export — 2 A4/667 919 bytes, обидва JPEG 2480×3508 px, повторений цінник має 0 відмінних pixel channels між сторінками. Poppler PNG обох сторінок переглянуті; фізична назва, ціна й одиниця на місці. Actual browser zoom200%, late encoder cancel/canvas0×0/cleanup/focus — PASS.
