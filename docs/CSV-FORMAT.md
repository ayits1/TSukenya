# Формат CSV TSukenya · версія 1

## Контракт

`app/csv.js` — одна реалізація для оболонки, legacy-експорту і React через `frontend/src/shared/csv.ts`. Кожен стовпець явно позначений `text` або `number`. CSV має подвоєні лапки, CRLF, роздільник `;` або `,`; завантаження мають UTF-8 BOM. Native створення CSV-бази використовує кому без BOM, як раніше.

Текст із початковими TAB/CR/LF або формульними `=`, `+`, `-`, `@`, їхніми fullwidth варіантами після пробілів/керівних символів отримує додатковий TAB **усередині лапок**. Це застосовується й до назви категорії, одиниці, складу чи іншого текстового стовпця. Справжній апостроф не знімається. Цей підхід описує [OWASP CSV Injection](https://github.com/OWASP/www-community/blob/master/pages/attacks/CSV_Injection.md); OWASP прямо зазначає відсутність універсальної гарантії для всіх редакторів і повторних збережень.

Numeric-поля не отримують TAB/апострофа. Serializer зберігає decimal strings, зокрема `-12.1234`, без перетворення через Number або округлення. Локалізована кома й правильно згруповані пробіли нормалізуються до десяткової крапки; неправильне число блокує експорт. Уже обчислені legacy numbers/двозначний формат цінника залишаються чинними адаптерами; serializer не виправляє попередню похибку floating point.

## Повторний імпорт

Експорти цінників, native CSV-база і ERP-шаблон мають суфікс ` [TSukenya CSV 1]` у першому заголовку. Це видима позначка формату у файлі. Parser прибирає її й рівно один службовий TAB, якщо решта клітинки відповідає правилу екранування. Справжня початкова табуляція може відновитися після зняття доданої. Звичайний зовнішній CSV без позначки не декодується; невідома версія отримує зрозумілу помилку. Подальша бізнес-нормалізація імпорту (trim назв/ID тощо) не змінена.

Залишки та звіт — однонапрямні експорти без суфікса: вони не є шаблонами імпорту. Копіювання їх як зовнішнього CSV не знімає TAB автоматично. CSV не замінює формат бізнес-документів.

Клієнт визначає роздільник поза лапками, відхиляє незакриті/неправильно розміщені лапки. Каталожний parser також розпізнає версію в Excel AoA й зберігає numeric-клітинки XLSX. Django `csv_format.read_rows` використовує strict CSV, визначає роздільник поза лапками, перевіряє дублікати заголовків і ширину рядків, повертає фізичні номери вихідних рядків. ERP preview залишає кількість і чотири знаки ціни під серверною Decimal-валідацією.

Не видаляйте суфікс версії перед повторним імпортом власного експортованого файлу: без нього відновлення службового екранування навмисно не виконується.
