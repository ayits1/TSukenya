# Цукерня — мережа магазинів солодощів

Бізнес-портал власника для мережі магазинів солодощів і кав'ярні.

Поточна вебверсія: [tsukernya.pp.ua](https://tsukernya.pp.ua/) (приватний вхід). Вона працює на окремому сервісі VPS; інструкція оновлення й відкату — у [документі розгортання](docs/SERVER-DEPLOYMENT.md). Автоматичний обмін із Google Sheets у цій вебверсії поки не підключено: товари завантажено зі знімка від 29.09.2026, а оновлення доступне через імпорт CSV/XLSX.

## Торговельний облік

Додано простір **Облік торгівлі**: закупівлі, склад, продажі й касові зміни, фінанси, клієнти, команда та звіти. Сервер — Django 5.2, основна база на VPS — PostgreSQL 18. Документи проводяться атомарно, повторні запити не дублюють рух, а скасування створює зворотні записи.

Зарплата: ставка за зміну + змінний відсоток від виторгу магазину за касову зміну. Умови зберігаються у табелі й нарахуванні; виплата та аванс відокремлені. Для початку введіть реальні магазини, працівників, початкові залишки й борги. Автоматичне ПРРО та податкову звітність не підключено.

Сценарії роботи, обмеження та перевірки — [CRM-IMPLEMENTATION.md](docs/CRM-IMPLEMENTATION.md).

## Що є

- `app/index.html` — оболонка; `app/portal.js` — поведінка порталу: етапи проєкту, задачі, ідеї, база товарів із цінами й націнками, витрати й точка беззбитковості, цінники (конструктор, друк, PDF, CSV).
  Окремо існує приватний Claude Artifact зі своїми даними та синхронізацією з Google-таблицею; його дані не перенесено на VPS автоматично.
- `server/` — Django API, обліковий журнал, авторизація, ролі та адаптер сумісності для браузера. `compose.production.yaml` запускає сервіс окремо від інших проєктів VPS.
- `data/baza-tovariv-template.xlsx` — шаблон бази товарів із фільтрами, закріпленим заголовком і списками вибору.
- `data/baza-tovariv-2026-09-29.csv` — знімок бази товарів на 29.09.2026.

## Синхронізація з Google-таблицею в Claude Artifact

Дашборд і Google-таблиця «База товарів (з фільтрами)» синхронізуються в обидва боки через конектор Google Sheets:

- зміни в таблиці з'являються в дашборді приблизно за хвилину, зміни в дашборді потрапляють у таблицю за кілька секунд;
- рядок таблиці пов'язаний із товаром через стовпець **ID** (його не можна змінювати);
- якщо одне поле змінили з обох боків, перемагає таблиця;
- видалений у таблиці рядок ховає товар у дашборді; видалений у дашборді товар очищує рядок у таблиці;
- «Ціна продажу» — ручна ціна; порожня означає «закупівля + націнка», підсумок видно в «Ціна на цінник».

Логіка синхронізації — чиста функція `planSync` між маркерами `SYNC-ENGINE-START/END` в `app/portal.js`. Перевірка сценаріїв: `node tests/sync-sim.js`.

## Робота з цінниками

У вкладці **Цінники** виберіть товари та копії. У конструкторі натисніть на елемент у списку або в макеті: праворуч з’являться його параметри шрифту, розміру у pt, кольору, насиченості, вирівнювання та видимості. Перегляд показує вибраний реальний товар, а ознака **Акція** з каталогу додає відповідну смугу на цінник.

Перед друком або PDF відкривається макет усіх аркушів А4. Вивід блокується, якщо немає ціни, текст не вміщується або вибрано понад 1000 копій. Застарілі ціни потребують підтвердження. Друкуйте в масштабі 100% без колонтитулів. Деталі дизайну, міграції та перевірки — у [описі оновлення](docs/PORTAL-REDESIGN.md).

## Робочі простори

**Операційна робота:** товари й ціни, цінники, поточні задачі з термінами, витрати. **Розвиток бізнесу:** ідеї, їх вибір та план реалізації. Задачі кожного простору зберігаються окремо за `scope`; старі задачі без `scope` належать до розвитку. Каталог має компактні колонки, сторінки, адаптивні блоки на телефоні та редактор товару в окремому вікні.

## Перевірки

`npm ci && npm test` — сценарії синхронізації. `PYTHON_BIN=.venv/bin/python npm run test:ui` — ізольована браузерна перевірка каталогу, акцій, конструктора, друку й робочих просторів. Вона використовує тимчасову базу та не змінює даних VPS.

Правила перевірки верстки, контролів і прототипів — [UI-QUALITY.md](docs/UI-QUALITY.md). Окрім загального переповнення, перевіряються відступи стрілок, висоти полів, клавіатура й фокус.

## Єдиний дизайн робочого застосунку

01.10.2026: напрям «Робочий простір» інтегровано та розгорнуто на VPS. Одна світла тема, бічна навігація за трьома просторами, компактний каталог і редагування в окремій панелі. У конструкторі — збільшений макет, властивості вибраного елемента та окремий блок товарів для друку; на телефоні елемент обирається селектом.

`app/ui.css` і `app/ui.js` — спільні контролі; `app/workspace.css` — компонування екранів. `app/portal.css` та `app/erp.css` зберігають сумісну геометрію в нижчому шарі `legacy`. Прибрано системне перемикання на темне оформлення. `design/workspace.html` залишається автономним демонстраційним каталогом.

Деталі — [DESIGN-PROPOSAL.md](docs/DESIGN-PROPOSAL.md), перевірки — [UI-QUALITY.md](docs/UI-QUALITY.md). `npm run test:layout:ui` перевіряє робочі екрани в Chrome, зокрема фактичний масштаб 200%; `QA_BROWSER=webkit npm run test:layout:ui` — WebKit. Обидва використовують тимчасову базу.

## Залежний пошук у Google-таблиці

У спільній [таблиці товарів](https://docs.google.com/spreadsheets/d/134HsmPHl97xsbCjcEVrFqqjv2Z2_3Qc1Fdhs1kLfNow/edit?gid=689512827#gid=689512827) додано аркуш **Пошук**. Аркуш **Товари** залишено першим для сумісності з уже опублікованим Claude Artifact. Вибір групи звужує доступні категорії, вибір категорії — пакування, а пакування — одиниці. Усі чотири списки та результати оновлюються з аркуша **Товари**. Якщо попередній вибір не відповідає новій групі, зверніть увагу на повідомлення над таблицею та встановіть відповідні значення. Результати на аркуші **Пошук** формуються формулою; редагуйте самі товари на аркуші **Товари**.


## Локальний запуск CRM

```sh
python3 -m venv .venv
.venv/bin/pip install -r server/requirements.txt
# OWNER_PASSWORD_HASH задається через приватне оточення; не зберігайте пароль у Git.
.venv/bin/python -m server.main
```

Локальна SQLite призначена для розробки. Для конкурентного обліку використовуйте PostgreSQL з production Compose.

```sh
ERP_DB_PATH=/tmp/tsukenya-tests.sqlite3 .venv/bin/python manage.py test tests.test_erp tests.test_security tests.test_migration tests.test_concurrency
PYTHON_BIN=.venv/bin/python npm run test:crm:ui
```

Перевірки конкуренції виконуються лише на PostgreSQL. Браузерні перевірки використовують окремі тимчасові бази.

Стек для подальшого зростання та поетапний перехід фронтенду — [STACK-EVOLUTION.md](docs/STACK-EVOLUTION.md). Це рекомендація; поточний інтерфейс залишається HTML/CSS/JavaScript.
